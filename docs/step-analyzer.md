# 記事に踏み順プレイヤーを埋め込む

Step Analyzerで譜面を作り、共有URLを記事本文に次の形式で1行として入れる。

```md
@[step-analyzer](https://step-analyzer-beta.vercel.app/?n=1000010000100001&b=150&f=48L&t=Practice "練習用の踏み順")
```

URLはStep Analyzerのクリップ共有から必要な小節だけ切り出して使える。
`n` / 圧縮された `d`、足指定 `f`、BPM `b`、停止 `s`、難易度 `df`、
変形 `tr`、ハイスピ `hs`、再生速度 `sp`、注目箇所 `hl` とコメント `hc` などはそのまま渡る。
URL中の空白や括弧はURLエンコードし、説明には半角ダブルクォートを含めない。

記事では自動再生せず、再生・速度変更・前後のステップ移動・譜面タップが使える。
編集は「Step Analyzerで開く」から行う。プレイヤーが利用できない場合もこのリンクは表示される。
譜面の配色は元ツールの判読性を維持する。

動画では、埋め込みの直後から同じ節の会話に元の矢印意匠を使った譜面レーンと3D足運びパネルが重なる。
最初の発言では共有URLの再生速度で全体を再生し、続く発言では `hl` のある小節を
半速でリプレイする（元の速度が0.25倍ならその速度を保つ）。注目指定がなければ
クリップ全体をスロー再生する。足指定、フリーズ、ジャンプ、空打ち、ショック、変形、
BPM変化と停止を解析に反映する。`hc` の注目コメントもパネルに表示する。

会話の文章は記事本文のWIRE/MONO行からそのまま使い、発言を自動生成しない。
章見出し（`###` / `####`）、次の画像、次の譜面、節の終わりで表示対象を切り替える。
後続の文章がない譜面には説明タイトルだけのカードを作る。
URL自体は読み上げ用テキストに入らない。

再生時間は本文と譜面の長さから決まる。通常の記事と同じカード数・尺の上限や
シーン上書きが適用されるため、必要な小節だけクリップして使い、スタジオの
シーン一覧で採用された内容を確認する。長い解説では `video.maxDurationInSeconds`
で全体の尺を確保できる。Shortsは本編から選ぶ予告編のため、譜面も抜粋になる。

プレビューとMP4書き出しは同じCanvas描画とフレーム時刻を使う。iframe録画や
動画生成サーバーは使わない。楽曲音源はURLから取り込まず、既存のBGMに、元のStep Analyzerのクラップ音を合成する。
クラップは譜面のBPM・停止・半速リプレイ・ループに同期する。譜面再生区間では
BGMを通常の20%へ滑らかに下げ、終了後0.35秒で戻す。打鍵音も抑えてクラップを優先する。
動画の足運びはStep Analyzerと同じ3Dの足・パネル・カメラを使う。
移動、交差、片足同時踏み、足上げ、保持中の発光をフレーム時刻で描画する。
3Dを初期化できない場合はエラーを表示し、2Dに置き換えた動画は書き出さない。

`/studio` の記事選択にデモ用の未公開SAMPLEを用意している。
`/studio/articles/sample-chart-conversation` はその記事本文の確認用。
実在曲の譜面・プレー記録・本人の発言ではない。

許可する配信元は `lib/content/step-analyzer.ts` に固定している。
ドメイン移行時はこの設定とテストを更新する。任意の外部サイトは埋め込めない。

反映順：Step Analyzerの `/embed` 対応を先に公開し、その後STEPWIRE側を公開する。
既存記事には自動で追加しない。例の譜面は練習用で、実在曲の譜面ではない。

曲解説（CHARTS）の横サムネイルは、heroImageと一致するkind: jacketの画像と、
最初の譜面URLの曲名t・アーティストst・難易度dfを使う。ジャケット全体を表示し、
難易度色の枠とStep Analyzer共通の足アイコン・レベルを添える。
記事のリズム解説は細かな秒数を避け、音符の種類・速さの比・数え方で説明する。
