# BPL sharing and browser history

- `/bpl/s?view=player&id=O4MA.` is a shareable HTML document, with server-rendered Open Graph and Twitter large-card metadata. It serves the existing standalone app without a redirect or a second Next layout. Crawlers do not need JavaScript.
- `/bpl/og` accepts the same parameters and returns a 1200×630 PNG. Match and head-to-head/matrix cards retain their existing layouts. Cards use archive records, the STEPWIRE vector logo and bundled OFL-licensed Japanese font; rendering makes no remote image requests.
- Team cards show all-time team-match wins/draws/losses, appearances and titles, plus the selected roster season. `rosterSeason` changes the pictured roster, never the statistics' scope. Unavailable or legacy `all` roster values use that team's latest registration season, matching the page.
- Player cards show the reviewed player illustration, latest registered affiliation, all-time appearances (ZERO included), Single song-level results/rate, and Duo **individual first places / songs**, including tied firsts. ZERO has no song-level EX SCORE records and is excluded from song statistics. A registration alone does not create a result. Win rate is wins / (wins + losses); an empty or all-draw record is `—`.
- `hideResults=1` excludes S6 results from totals and identifies that scope on the card. Selected S6 membership is not represented as S6 results.
- Only the inventoried local WebP illustrations in `docs/bpl-generated-portraits.json` are used. Sharp, already required by Next and now declared directly, converts those images to PNG for Satori. Original portraits are unchanged. The deployment tracing includes portrait files. No official logos or source photos are bundled.
- `/bpl` rewrites to the HTML handler. Legacy hash links remain usable, including punctuation in player IDs, but hashes are not sent to servers. On entry and navigation, the browser URL becomes a server-readable `/bpl/s?view=...` URL.
- `public/bpl/routing.js` is the URL-state codec. Initial load, popstate and hashchange use the same complete state restoration; duplicate history events do not render twice. Normal view/season navigation pushes a history entry. Search and filters replace the current entry synchronously, so Back/Forward cannot lose the final typed query. Sharing reads state; it never rewrites history from a MutationObserver.
- Opening a match pushes a modal history entry and retains the underlying view/filter state. Back or close/Escape/backdrop returns to that entry; Forward reopens the match. An unchanged background DOM preserves its opener and scroll. A directly opened match safely closes to its season (S6 guide for S6), replacing the direct-link entry rather than leaving the site.
- Native Web Share runs directly from a click. Unsupported browsers copy the URL; clipboard failure exposes a selected readonly URL. Cancelling the native share sheet is not an error. Preview failures have a visible retry instruction.
- `lib/bpl/share.ts` validates entity IDs and enums before rendering metadata/cards. User text is escaped. Unknown IDs return 404. The image never prints arbitrary search text or fetches a user-supplied image URL.
- Entity URLs include `summaryVersion=1`; image URLs also contain a revision derived from data, branding and the reviewed portrait inventory. Bump the summary version when changing the design. CDN caching remains HTML 1 hour/images 1 day; social networks have independent caches and may delay already-posted previews.

## Regression checks

- `pnpm test` covers all entities, raw-statistic edge cases, metadata before scripts, and the actual standalone renderer with a simulated browser history. It includes repeated Back/Forward, roster/filter restoration, modal exits, ZERO, legacy links, punctuation, newcomer records and injected future S6 results.
- `pnpm test:bpl:images` calls both server handlers and validates 54 distinct PNGs, including every player/team, a historical roster, a match and the matrix. Optional `BPL_IMAGE_OUTPUT=/path` saves cards for visual inspection. This is still-image verification, not a video render.
- `pnpm exec playwright install chromium` then `pnpm test:bpl:browser` against `pnpm start` or `pnpm dev` runs the real-browser regression suite. `BASE_URL` can select another authorized server and `CHROMIUM_PATH` an installed browser. The suite checks navigation, copied/share-preview URLs, close/Escape/backdrop, opener focus and future S6 visibility. It must run in an environment allowing normal browser sockets; do not bypass a denied environment restriction.
- CI runs all three suites. Visually inspect representative player/team cards and desktop/mobile navigation on the preview before publishing.
