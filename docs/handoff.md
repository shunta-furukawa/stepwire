# Handoff — 材料を渡して記事にしてもらう

MONO DDR が材料を渡し、Claude が記事に仕上げる体制の約束事。
「よしなに」の中身をここに固定しておく。曖昧なままだと、AI が事実を足す。

## 記事の形

STEPWIRE の記事は三つの節で、この順番。節の名前は記事ごとに付け替えられる
（frontmatter の `labels`）。事実と分析の区別は変わらない。

| 節 | 既定の名前 | セッション記事での名前 | 中身 |
| --- | --- | --- | --- |
| 1 | NEWS | NEWS | 外部の変化・更新。解禁、イベント、告知。出典を引く。 |
| 2 | CONTEXT | SESSION | 私のセッションのラップアップ。何を踏んで、どうだったか。 |
| 3 | PLAYER IMPACT | PICKUP | ピックアッププレイ。X に投稿したリザルトと、その話。 |

**文章は「私」で書く。** STEPWIRE は MONO DDR の媒体で、記事は本人の投稿として
読まれる。「MONO DDR は…と述べた」ではなく「私は…」。自分の X ポストは自分の
記録として `[^n]` で引く。

## 渡すもの

最低限は一つ目だけ。あとは有れば良くなる。

1. **起点のポスト URL。** 公式アカウントの告知、大会の結果、自分の投稿。
2. **セッションログ。** e-amusement の「最近プレーした楽曲」のスクリーンショット。
   曲、難易度、スコア、ランク、時刻がこれで揃う。レベルは載らないので、
   リザルト写真があればそこから読む。
3. **リザルト写真。** ピックアップにする曲のもの。レベル、コンボ、判定内訳が読める。
4. **感想。** 一行でも、録音でも、ポストの文面でも。
   **本人の言葉が無いところに感想は書かない。** 足りなければ Claude が
   このセッションで質問する（下記）。
5. **温度。** `importance` を `breaking` / `major` にするかは本人の判断。

## こちらがやること

```bash
pnpm article:from-post <URL> --category CHARTS   # 骨組み
```

1. ポストを公式 oEmbed API で読む（`lib/news/oembed.ts`）。スクレイピングは
   しない。画像は取りに行かず、渡されたものを `public/images/articles/<日付-slug>/`
   に置いて credit を書く。本人の写真は `MONO DDR`。
2. NEWS は出典の範囲を一歩も出ない。日付、曲名、作家名、時刻は告知に書いてある
   とおり。告知に無い「なぜ」「どういう位置づけか」は NEWS に書かない。
3. SESSION はログから `plays` 図（`docs/figures.md`）を起こし、本文は写真と
   ログから読める事実に本人の言葉を足して組む。
4. PICKUP はリザルト写真の数字（スコア、レベル、コンボ）と本人の投稿の引用。
   **写真は、その譜面を語る段落の直前に置く**（`![](images/…)` を一行で）。
   動画ではその段落のカードに写真が並び、ページでは段落の前に写真が出る。
   本文に置かなかった写真だけが、NEWS のあとのギャラリーに回る。
5. **AI の推測を本人の意見のように書かない。** 感想が足りなければ、記事を
   `review` で push した上で、具体的に質問する。質問は「どの曲が一番きつかった
   か」「E ランクの2曲は何があったか」のように、答えれば一文になる粒度で。
6. BGM は `docs/audio-sources.md` の役割表から選ぶ。
7. `pnpm content:validate` を通し、`status: review` で push する。

## 本人がやること

1. 記事を読む。特に SESSION と PICKUP が自分の言葉になっているか。
2. 質問に答える。答えが入った版を Claude が push する。
3. `status: published` にする（または「公開して」と言う）。**公開は本人の判断。**
   Claude は `review` までしか上げない。
4. スタジオで動画を書き出して投稿する。

## 書かないこと

- 告知に無い日付、曲数、仕様。
- 本人が言っていない感想、評価、比較。
- 写真から読めない桁。読めない数字は図に入れない。
- ゲーム内楽曲やプレイ動画の音声。
- 他人のポストの画像を、本人の判断なしに。

## 例

2026-09-03 の「EXTRA SAVIOR WORLD に 7th MUSIC CREATOR AUDITION の3曲」が
この体制で書いた最初の記事。渡されたのは公式の告知ポスト、本人のプレイ報告
ポスト、セッションログのスクリーンショット。NEWS は告知のとおり、SESSION は
ログの10プレイを `plays` 図にして本文を組み、PICKUP はリザルト写真の3曲と
本人の投稿の引用。
