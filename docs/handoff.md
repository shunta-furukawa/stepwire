# Handoff — 材料を渡して記事にしてもらう

MONO DDR が材料を渡し、Claude が記事に仕上げる体制の約束事。
「よしなに」の中身をここに固定しておく。曖昧なままだと、AI が事実を足す。

## 渡すもの

最低限は一つ目だけ。あとは有れば良くなる。

1. **起点のポスト URL。** 公式アカウントの告知、大会の結果、本人の投稿。
   複数あれば全部。どれが事実（NEWS）でどれが感想（CONTEXT / PLAYER IMPACT）
   かは、こちらで振り分ける。迷えば聞く。
2. **感想。** 一行でも、録音でも、ポストへの自己引用でも。
   **本人の言葉が無いところに感想は書かない。** 無ければ CONTEXT は
   観察できる事実（譜面レベル、リザルトの数字）だけで組む。
3. **写真。** リザルト、筐体、会場。ポストに付いていれば URL だけで足りる。
   本人の写真は credit `MONO DDR`。他人の画像は、使ってよいかを本人が決める。
4. **温度。** `importance` を `breaking` / `major` にするかは本人の判断。
   言われなければ `normal`。

## こちらがやること

```bash
pnpm article:from-post <URL> --category CHARTS   # 骨組み
```

1. ポストを公式 oEmbed API で読む（`lib/news/oembed.ts`）。スクレイピングは
   しない。画像は取りに行かず、渡されたものを `public/images/articles/<日付-slug>/`
   に置いて credit を書く。
2. NEWS は出典の範囲を一歩も出ない。日付、曲名、作家名、時刻は告知に書いてある
   とおり。告知に無い「なぜ」「どういう位置づけか」は NEWS に書かない。
3. CONTEXT と PLAYER IMPACT は本人の言葉と観察できる事実から組む。本人の発言は
   引用符で括り、`[^n]` を付ける。**AI の推測を本人の意見のように書かない。**
4. 図（`figures`）は写真や告知から読み取れる数字だけ。読み取れない桁は入れない。
5. BGM は `docs/audio-sources.md` の役割表から選ぶ。
6. `pnpm content:validate` を通し、`status: review` で push する。

## 本人がやること

1. 記事を読む。特に CONTEXT と PLAYER IMPACT が自分の言葉になっているか。
2. 直す。直してほしい所を言うだけでもいい。
3. `status: published` にする（または「公開して」と言う）。**公開は本人の判断。**
   Claude は `review` までしか上げない。
4. スタジオで動画を書き出して投稿する。

## 書かないこと

- 告知に無い日付、曲数、仕様。
- 本人が言っていない感想、評価、比較。
- ゲーム内楽曲やプレイ動画の音声。
- 他人のポストの画像を、本人の判断なしに。

## 例

2026-09-03 の「EXTRA SAVIOR WORLD に 7th MUSIC CREATOR AUDITION の3曲」が
この体制で書いた最初の記事。渡されたのは公式の告知ポストと本人のプレイ報告
ポストの URL 二つ。NEWS は告知のとおり、CONTEXT はリザルト写真から読める
レベル差、PLAYER IMPACT はスコアと本人の投稿の引用で組んである。
